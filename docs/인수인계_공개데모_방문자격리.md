# 인수인계 — 공개 데모 방문자 격리 · 3D 섬 공용화 (2026-09-20)

> 대상: 대시보드 / 학생 화면 / 교사 화면 / 민준이의 섬 담당자.
> 이 문서는 **담당자별로 반드시 지켜야 할 것**과 **검증 명령**만 요약한다. 상세 근거·적용 이력은 아래 "관련 문서"를 본다.
> 현재 상태: 공유 DB에 1094 + 공용 시드 15종 적용 완료, `main`에 병합됨, Vercel **Preview** 스모크(A/B 격리) 통과. Production 외부 공개는 아직 아니다.

## 1. 담당자별 핵심 인수인계
| 담당자 | 핵심 인수인계 |
|---|---|
| **대시보드** | `dashboardScope.ts`의 **방문자 범위 필터를 유지**해야 한다. 관리자(admin) 클라이언트는 RLS를 우회하므로 `enrollment_id`만으로 조회하면 다른 방문자 데이터가 섞인다. **상담 신청·갈등 기록은 공용 시드 또는 현재 방문자 데이터만** 조회해야 한다. 검증은 `npm run test:dashboard-scope`. |
| **학생 화면** | 최초 진입은 `/demo-init`에서 **익명 사용자를 생성**한다. **Preview URL이 바뀌면 새로운 익명 사용자로 인식되는 것이 정상**이다(쿠키가 origin 단위). `client.ts`의 `NEXT_PUBLIC_*` **직접(정적) 참조를 동적 `process.env[name]`으로 되돌리면 Vercel에서 로그인이 깨진다.** 아이템 폴링은 **순차 요청 · 12초 요청 타임아웃 · 재시도 백오프 구조를 유지**해야 한다. |
| **교사 화면** | **A 방문자의 녹음·관찰·상담 데이터가 B에게 노출되면 안 된다.** 기존 공용 데모 기록은 둘 다 볼 수 있다. **관리자 클라이언트 조회에는 항상 현재 `viewerTeacherId`/방문자 스코프를 적용**해야 한다. 업무기록 직접 작성 A/B 수동 테스트는 생략했지만 관련 자동·정책 테스트는 통과했다. |
| **민준이의 섬** | **DEMO_MODE에서는 DB 공용 15개 + 현재 방문자 개인 아이템만 표시**한다. 공용 15개는 **`locked:true`라 이동·삭제할 수 없다.** 개인 아이템은 **UID별 섬에 누적**된다. **`/island`는 저장형 섬이 아닌 독립 확인 화면**이며, 실제 검증 경로는 **`/checkin` 완료 후 섬**이다. **공용 15종에는 기존 민준 섬의 `note` 연출이 없으며, `note` 추가는 후속 작업**이다(§5 참고). |

### 1-1. 공통 전달 사항 (전 담당자)
1. **공유 Supabase에는 1094와 공용 시드 15종이 이미 적용돼 있다. 다시 실행하면 안 된다.** (마이그레이션 재적용·`seed-public-island.sql` 재실행 금지. 시드 SQL은 중복 실행을 스스로 거부하지만, 어떤 경우에도 실행하지 않는다.)
2. **공용 시드와 테스트 아이템은 봉인돼 있다. 임의로 UPDATE/DELETE 하면 안 된다.** (`student_items`는 봉인 트리거로 수정·삭제가 막혀 있고, 공용 섬·배치는 시드 관리 세션 밖에서 수정·삭제할 수 없다. 정정이 필요하면 별도 승인 후 절차를 따른다 — §5.)
3. **실제 Preview에서 A의 개인 아이템 '풍선'이 B에게 보이지 않는 것까지 확인했다.** (공용 15개는 A·B 동일, B의 `locked:false` 0개. 상세: `Vercel_Preview_배포_체크리스트.md` §7.)
4. **main의 코드 기준 최종 병합 커밋은 `9434544`이다.** 그 이후 main에는 **문서 커밋만** 추가됐다(코드 변경 없음). 현재 main 최신 커밋은 `git log -1 main`으로 확인한다.
5. **`/item-lab/*`는 Preview 보호(Deployment Protection) 아래에서만 사용하고, 외부 Production 공개 전에 반드시 차단**(404 또는 인증/접근 제한)해야 한다.
6. **학생 대화·아이템 생성 등 대부분의 AI 경로에는 앱 전체 호출 한도가 없다.** 제공업체(OpenAI·Anthropic) 콘솔의 월 한도에 의존하며, **Production 공개 전에 후속 제한 검토가 필요**하다(§5).
7. **새 배포에서도 `DEMO_MODE=true`와 Supabase·AI 환경변수를 먼저 설정해야 한다.** `NEXT_PUBLIC_*`는 빌드 때 번들에 고정되므로 변수 등록 → 배포 순서를 지킨다. Vercel 환경변수는 현재 **Preview 스코프에만** 있고 Production에는 없다(`Vercel_Preview_배포_체크리스트.md` §1·§2).
8. **이 Vercel 프로젝트(`ai-wanted`, 팀 JIHYEON)는 팀원의 별도 Vercel 배포와 무관하다**(사용자 제공 정보). 팀원 배포에 이 프로젝트의 환경변수·도메인이 적용되지 않는다.
- **AI 하루 요약의 DB 저장(1095)** — 상세 화면과 협진 챗봇이 같은 저장 요약(`queries/sessionSummaries.ts`)을 읽도록 로컬 구현·검증을 마쳤다(브랜치 `feature/jihyeon-session-summary-db`). **공유 DB 미적용·앱 미배포**이며, 적용은 별도 승인 후 `docs/데모_방문자_격리_적용_절차.md` §17-7·§17-9 순서(DB 먼저, 앱 나중)로 한다. 챗봇에는 대화 원문을 넣지 않고 저장된 요약만 쓴다.

## 3. 지켜야 할 공통 원칙
1. **admin(service_role) 클라이언트는 RLS를 우회한다.** 서버 코드가 데이터를 읽을 때는 항상 방문자 스코프를 직접 건다(RLS는 PostgREST 직접 호출에 대한 방어선일 뿐이다).
2. **방문자 전원이 같은 학생(민준)·같은 반을 공유한다.** `enrollment_id`/`class_id` 단위 조회는 방문자 간 혼입의 원인이다.
3. **공용 데이터**: 공용 시드(부모 체크인·발화·job 없음)와 공용 아이템·섬·배치는 DB 트리거·봉인 정책으로 방문자(및 앱 코드)가 수정·삭제할 수 없다. 응답에는 이름·모양·좌표만 내려준다.
4. **부모 체크인·발화·`item_generation_jobs`는 공개하지 않는다.**
5. 새 조회를 추가하면 **공용 시드 + 현재 방문자** 범위인지, **대조군(공용·본인 데이터가 보이는지)** 을 함께 검증하는 테스트를 추가한다.

## 5. 알려진 사항 · 후속 항목
- **Preview에서 미확인**: 상담 신청 격리, 재입장(쿠키 삭제 후 새 익명 계정). 자동 테스트로는 검증됨(위 명령), Preview 브라우저 확인은 아직.
- **기존 테스트 실패(이번 변경과 무관, 기준선과 동일)**: 섬 단위 테스트 `placement` 2개, `puzzle` 로드 실패, `islandTerrain` 1개, `pieceLandscape`의 `PROP_REACH` 1개. `scripts/test-item-generation-wait.cjs`도 라우트 의존성 문제로 이미 실패 상태.
- **민준 섬 `note` 연출**: **공용 15종에는 기존 민준 섬의 `note` 연출이 없으며, `note` 추가는 후속 작업**이다. main의 코드 기반 18개 배치의 `note`(눌러 보는 발화 시점·사유)는 **DEMO_MODE(공개 데모)에서 보이지 않는다.** 섬 담당자 후속 결정 필요(공용 15종에 큐레이션 `note`를 두는 방안, 또는 공용 시드를 민준 18개로 교체) — 부모 체크인·발화를 공개하지 않는 원칙은 유지.
- **`/item-lab/*` 노출**: 프로덕션 빌드에서도 페이지가 열린다. **Production 외부 공개 전에 404 처리 또는 인증/접근 제한이 필수**(Production 배포 담당자 인계 항목).
- **AI 비용 제한**: 앱 내 호출 제한은 협진 챗봇(`teacher-agent`) 한 경로에만, 방문자별 시간당 30회. 그 외 AI 경로는 앱 수준 제한이 없고 프로젝트 전체 일일 상한·통합 금액 상한도 없다. OpenAI·Anthropic 콘솔의 월 한도에 의존한다. **Production 공개 전 후속 검토.**
- **데이터 잔재**: 테스트가 만든 익명 계정·체크인·아이템·개인 섬·배치·자산은 봉인 트리거 때문에 지워지지 않는다. 공용 시드 아이템을 정정하려면 봉인 트리거를 잠시 끄는 별도 승인이 필요하다.
- **DB 롤백 순서**: 방문자·공용 데이터가 생긴 뒤에는 1094 전체 롤백이 거부된다(부분 롤백 = 정책 잠금만). DB 전체 롤백 시 새 코드도 함께 되돌려야 한다.
- **AI 요약 표시·생성 범위 밖(후속)**: ① 시드(mock) 요약을 실제 AI 요약과 구분 표기하지 않음 ② 공용 요약과 개인 요약을 병기하지 않음(본인 세션이 있는 날은 본인 요약만, 없으면 "없음") ③ 공용 세션 요약의 생성 권한·횟수 제한 없음. **기간 요약(`consultation_period_summary`)은 이번 범위 밖**이라 여전히 서버 메모리에 저장된다. 상세: 절차 문서 §17-8.

## 6. 배포(Vercel) 현황
- 프로젝트 `ai-wanted`(팀 JIHYEON, hobby). **GitHub 미연결** — 푸시해도 자동 배포가 생기지 않는다. 배포는 CLI로 수동(`npx vercel deploy --target=preview --yes --scope jihyeon`, **`--prod` 금지**).
- 환경변수는 **Preview 스코프에만** 등록돼 있다(이름 10개). Production·Development에는 없다.
- **첫 배포가 실수로 Production 타깃**이 되어 Production 배포 1건이 존재한다(환경변수 없음, Deployment Protection으로 보호). 처리 여부는 별도 결정.
- Deployment Protection은 **All Deployments + Vercel Authentication** 유지.
- 상세: `Vercel_Preview_배포_체크리스트.md`.
