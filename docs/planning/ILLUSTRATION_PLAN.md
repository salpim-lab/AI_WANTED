# 일러스트 에셋 확보 방안

> 첫 화면(등·하교) 목업 수준의 일러스트를 실제로 확보하기 위한 계획.
> 작성: 2026-09-15 · STU-001-B (Claude 세션)

## 왜 이 문서가 필요한가

유민님이 보내주신 목업의 일러스트(아이·선생님·학교·봉투)는 **AI로 생성된 그림**이다.
현재 코드의 일러스트는 내가 SVG 도형(`path`, `circle`, `ellipse`)을 손으로 조립한 것이라,
그라데이션과 음영을 넣어도 **목업의 그림체에는 구조적으로 닿지 못한다.**

- SVG 수작업으로 가능한 것: 평면적 도형, 단순 음영, 기하학적 형태 (학교 건물, 봉투, 구름)
- SVG 수작업으로 불가능한 것: 부드러운 명암, 머리카락 질감, 손그림 특유의 선, 표정의 미묘함

**즉 캐릭터는 코드로 못 그린다.** 실제 이미지 파일이 필요하다.

## 결정: 학생 사진 대신 공용 마스코트 (2026-09-15)

한 반에 학생이 많아 **학생마다 일러스트나 사진을 준비하는 것은 MVP 범위에서 불가능**하다.
그래서 모든 학생이 같은 **살핌 마스코트**를 본다. 선생님만 실제 인물 기반 일러스트다.

부수 효과가 크다. **학생 사진은 개인정보라 학부모 동의 절차가 필요**한데, 공용 마스코트는
그 문제를 통째로 없앤다. 제작 비용뿐 아니라 법적으로도 더 나은 선택이다.

### 마스코트 설계 시 주의

목업의 캐릭터는 **남자아이**다. 이걸 그대로 전교생 공용으로 쓰면
여학생은 자기와 다른 성별의 아이를 매일 마주하게 된다. 공용 캐릭터는
**성별·외모가 특정되지 않는 쪽**이 안전하다. 세 방향이 있다.

| 방향 | 설명 | 장단 |
|---|---|---|
| **동물·사물 캐릭터** | 살핌 로고의 웃는 얼굴을 캐릭터로 확장 | 성별 문제 없음, 브랜드와 일관 |
| **중성적인 아이** | 성별 단서를 뺀 아이 캐릭터 | 친근하지만 완전 중립은 어려움 |
| **남/여 2종** | 학생 프로필의 성별로 분기 | 이미지 2배, 성별 입력 필요 |

MVP 기준으로는 **동물·사물 캐릭터**를 권한다. 로고에 이미 웃는 얼굴이 있어
그걸 그대로 캐릭터로 키우면 브랜드 자산이 하나로 모인다.

## 스타일 방향: 살핌 미니어처 세계 (soft 3D)

강윤지님이 Blender 로 학생 섬을 3D로 만들고 있다. 아이는 **한 흐름 안에서**
첫 화면 → 색 선택 → 대화 → 아이템 → 섬까지 30초 만에 이동한다.
첫 화면이 납작한 2D 인데 마지막이 3D 섬이면 **같은 세계로 느껴지지 않는다.**

그래서 **레이아웃과 구성은 지금 목업 그대로 두되, 그림체만 soft 3D 로 통일**한다.
마스코트 · 학교 · 편지 · 구름 · 나무가 하나의 점토 미니어처 세계처럼 보이게 한다.

### Blender 는 3D 를 위해서가 아니라 **통일감을 위해** 쓴다

결과물은 **2D 정지 이미지**다. Blender 를 쓰는 이유는 3D 로 보이게 하려는 게 아니라,
여러 에셋이 **같은 조명 · 같은 카메라 · 같은 재질**을 갖도록 강제하기 위해서다.

이게 AI 이미지 생성의 가장 약한 지점이다.

| | AI 생성 | Blender 렌더 |
|---|---|---|
| 에셋 1개 만들기 | 빠르다 | 느리다 (모델링) |
| **에셋 N개의 일관성** | **매번 주사위. 조명·재질이 미묘하게 어긋난다** | **설계상 보장. 같은 씬에서 렌더** |
| **같은 캐릭터 다른 포즈** | **가장 못하는 일. 얼굴이 바뀐다** | **리그 한 번, 포즈만 교체** |
| 크기·각도 다시 뽑기 | 불가능. 다시 생성 | 무료. 재렌더 |
| 나중에 에셋 추가 | 예전 것과 안 맞음 | 같은 씬에 추가하면 끝 |

초기 세팅 비용은 Blender 가 크지만, **에셋이 여러 개이고 앞으로 더 늘어난다면**
(등·하교 외 화면, 마스코트 추가 포즈, 시즌 변형) 금방 역전된다.
특히 마스코트 등교/하교 2포즈는 AI 가 제일 못하는 경우라 Blender 가 확실히 유리하다.

> 강윤지님이 이미 blender-mcp 를 쓰고 있다. **시간을 빌리는 게 아니라
> 이미 팀 안에 있는 노하우를 참고**하면 진입 비용이 줄어든다.

### 그래도 첫 화면은 실시간 3D 가 아니다 — 중요

| | 섬 | 첫 화면 |
|---|---|---|
| 상호작용 | 드래그 배치, 카메라 조작 | **없음. 안 움직이는 그림** |
| 필요한 것 | Three.js + GLB | 이미지 한 장 |

첫 화면에 Three.js 를 얹으면 번들 · GPU · 로딩이 전부 순수 비용이다.
학교 태블릿 성능도 변수고, 기획안의 **"색 신호등 3초 · 전체 30초"** 예산을
첫 화면 로딩이 갉아먹는다.

**soft 3D 는 "룩"이지 런타임 기술이 아니다.** Blender 로 만들든 AI 로 만들든
결과물은 **투명 배경 정지 이미지(WebP)** 이고, 파이프라인과 코드는
앞서 정한 것에서 한 글자도 바뀌지 않는다. 소스만 바뀐다.

### 스타일 규약 — 먼저 정하고 시작할 것

이게 안 맞으면 "같은 세계"가 아니라 **짜깁기**가 된다.
Blender 로 간다면 **이 값들이 곧 씬 세팅**이고, 한 번 정하면 그 뒤로는 자동이다.

화면 소유는 유민님께 있으므로 제작을 부탁하는 게 아니라,
**섬의 렌더 설정값만 확인**해서 같은 값을 쓰면 된다.

| 항목 | 확인할 것 | 현재 2D 기준 |
|---|---|---|
| **조명 방향** | 키 라이트가 어느 쪽 위인가 | 왼쪽 위 |
| **카메라 각도** | 정면인가 3/4 부감인가 | 정면 (섬이 부감이면 맞춰야 함) |
| **재질** | 무광 점토인가 반광인가 | — |
| **색온도·채도** | 등교(맑음)/하교(노을) 두 조명 세트 | 등교 크림+하늘색, 하교 라벤더→피치→노랑 |

`style_version` 도 같은 값을 달아둔다. 나중에 섬 스타일이 바뀔 때 브랜드 에셋도 같이 찾아진다.

### 마스코트를 Blender 로 만들면 섬에도 쓸 수 있다

Blender 로 모델링해 두면 **정지 이미지로 내보내는 동시에 GLB 로도 내보낼 수 있다.**
그러면 아이가 자기 섬에서 첫 화면의 그 캐릭터를 다시 만난다.
같은 모델이 두 화면을 먹여살리는 구조라, **마스코트만큼은 Blender 가 확실히 남는다.**

반대로 구름 · 나무 · 덤불은 첫 화면에서만 쓰이고 색도 아침/노을로 바뀌어야 하므로
**SVG 로 두는 게 맞다** (아래 "이미지로 빼지 말 것" 참고).

### 만약 AI 로 간다면

Blender 초기 비용이 부담되면 AI 로 시작해도 된다. 다만 위험을 알고 시작할 것.

- **공통 스타일 접미사를 한 글자도 바꾸지 말 것.** 그래도 완전히는 안 맞는다
- **마스코트 2포즈는 한 번에 요청**하는 편이 낫다 (같은 캐릭터 두 포즈를 한 이미지에 생성 후 분리)
- 나중에 에셋을 추가하면 기존 것과 안 맞을 각오를 할 것

## 권장안 — AI 생성 + 투명 배경 이미지

목업 자체가 AI 생성물이므로, **같은 방식으로 요소별로 따로 생성**하면 그림체가 맞는다.
가장 빠르고 비용이 낮으며, 이미 코드가 슬롯으로 준비되어 있어 파일만 넣으면 끝난다.

### 필요한 파일 목록

**저장 위치는 반드시 `public/` 이다.** Next.js 는 `public/` 만 URL 로 서빙한다.
저장소 루트의 `assets/` 는 강윤지님의 3D 작업 공간이라 여기에 넣으면 규칙이 충돌하고,
빌드에도 포함되지 않아 404 가 난다.

| 파일 | 내용 | 권장 크기 | 배경 | 필수 |
|---|---|---|---|---|
| `public/brand/mascot-wave.webp` | 마스코트 · 등교 포즈 | 높이 1200px 이상 | **투명** | O |
| `public/brand/mascot-listen.webp` | 마스코트 · 하교 포즈 | 높이 1200px 이상 | **투명** | O |
| `public/brand/teacher-yumin.webp` | 선생님 얼굴, 원형 크롭용 | 512×512 | 무방 | O |
| `public/brand/school.webp` | 학교 건물 | 너비 900px 이상 | **투명** | 선택 |
| `public/brand/envelope.webp` | 봉투 (편지지 제외) | 너비 1200px 이상 | **투명** | 선택 |
| `public/brand/salpim-logo.svg` | 살핌 로고 | 벡터 | 투명 | 선택 |

> 투명 배경이 핵심이다. 배경이 박힌 이미지는 아침/노을 두 배경 위에 못 올린다.
> WebP 는 알파 채널을 지원한다. 다만 **AI 가 내보낸 원본 PNG 도 함께 보관**할 것 —
> WebP 에서 재변환하면 손실이 누적된다.

### 이미지로 빼지 말 것 — 코드에 SVG 로 둔다

`SceneBackdrop.tsx` 의 **구름 · 언덕 · 나무 · 덤불 · 하늘 그라데이션**은 파일로 빼지 않는다.

- **색이 바뀐다.** 구름은 등교에 파랑(`--sp-cloud`), 하교에 분홍(`--sp-cloud-dusk`)이다.
  이미지로 빼면 파일이 2배가 되고 배경을 손볼 때마다 다시 만들어야 한다
- **크기가 자유로워야 한다.** 언덕은 화면 전체 폭으로 늘어난다. 래스터는 늘리면 뭉갠다
- **도형이라 SVG 로 충분하다.** 사람 얼굴과 달리 곡선으로 재현이 된다

즉 **이미지가 꼭 필요한 건 사람(마스코트·선생님)** 이고, 학교와 봉투는 선택이다.

> soft 3D 로 통일할 때도 이 원칙은 그대로다. 구름·나무를 이미지로 빼면
> 아침/노을 색 전환이 막히고 파일이 2배가 된다. 대신 현재 SVG 에
> 그라데이션과 그림자를 얹어 점토 느낌에 가깝게 맞추는 쪽이 낫다.

### 생성 프롬프트 (영문이 결과가 안정적이다)

공통 스타일 접미사 — **모든 프롬프트 끝에 똑같이 붙인다.** 이게 세계관을 묶는다:

```
soft 3D clay render, miniature diorama style, rounded matte surfaces,
soft global illumination, gentle soft shadows, key light from upper left,
pastel palette, children's toy-like proportions, centered, front view,
transparent background, no text, no watermark
```

> 접미사를 한 글자라도 다르게 주면 그림체가 미묘하게 어긋난다. 복사해서 붙일 것.
> 카메라 각도(`front view`)와 조명(`key light from upper left`)은
> 위 스타일 규약에서 윤지님 값을 확인한 뒤 맞춰서 고친다.

**마스코트** (성별이 특정되지 않는 캐릭터 · 등교 포즈 / 하교 포즈 두 장)
```
A friendly gender-neutral mascot character for a children's emotion check-in app,
a soft round character with a simple smiling face, big round eyes, rosy cheeks,
wearing a small blue hoodie and a little backpack, standing and greeting
```
하교용은 끝에 `waving one hand cheerfully` 를 붙여 **포즈만** 바꾼다.
두 장의 그림체 · 색 · 크기가 같아야 화면 전환이 자연스럽다.

**선생님**
```
A friendly young Korean female elementary school teacher as a soft clay figurine,
shoulder-length dark brown hair, warm smile, wearing a lavender blouse with white collar,
head and shoulders, facing forward
```

**학교**
```
A small cute elementary school building as a clay miniature model, cream ivory walls,
orange-terracotta triangular roof, round analog clock on the facade, three square windows,
small orange flag on a flagpole
```

**봉투**
```
An open pastel lavender purple envelope as a soft clay miniature, front flap folded down,
a small purple heart wax seal in the center, soft rounded edges, gentle depth
```

### 코드는 이미 준비되어 있다

파일만 넣으면 아래 한 줄로 교체된다. 컴포넌트 수정 불필요.

```tsx
// checkin/page.tsx, checkout/page.tsx
<StudentOpening
  active={flow.step === 1}
  period="morning"
  onNext={() => flow.goTo(2)}
  character={{
    kind: "mascot",
    src: "/brand/mascot-wave.webp",          // 하교는 mascot-listen.webp
    alt: "",
  }}
/>
```

선생님 아바타도 동일하다.

```tsx
letter={{
  text: "어제 수학 시간에 발표하는 모습이\n정말 멋졌어! 💜",
  teacherName: "이유민 선생님",
  avatarSrc: "/brand/teacher-avatar.png",
}}
```

`kind` 는 두 갈래를 받는다.

- `"mascot"` — **MVP 에서 쓰는 값.** 테두리 없이 그대로 얹힌다
- `"photo"` — 학생 실사진. 흰 테두리 + 위쪽 라운드 + 그림자가 붙는다.
  지금은 쓰지 않지만 나중을 위해 남겨 둔다. 쓰게 되면 저장 위치가 달라진다 (아래 표)

### 브랜드 일러스트와 학생별 이미지는 다른 것이다

| | 브랜드 일러스트 (마스코트·선생님) | 학생 사진 (지금은 미사용) |
|---|---|---|
| 저장 위치 | `public/brand/` | Supabase Storage |
| 접근 | 공개 URL | signed URL |
| 빌드 포함 | O | X |
| 개인정보 | 없음 | **있음 — 학부모 동의 필요** |

강윤지님의 3D 에셋이 Supabase Storage + signed URL 로 가기로 한 것과 같은 이유다.

## 대안들

| 방안 | 장점 | 단점 | 적합한 때 |
|---|---|---|---|
| **AI 생성** (권장) | 즉시, 무료~저가, 목업과 같은 그림체 | 요소마다 시도 반복 필요, 상업 이용 조건 확인 필요 | 지금 POC 단계 |
| **스톡 일러스트** (Freepik, Storyset, Icons8 Ouch!) | 품질 보장, 세트로 그림체 통일, 라이선스 명확 | 우리 캐릭터가 아님, 월 구독 | 빠르게 완성도가 필요할 때 |
| **외주 일러스트레이터** | 완전한 소유권, 브랜드 고유 캐릭터 | 비용·기간 | 제품이 확정된 뒤 |
| **Lottie / Rive** | 캐릭터가 움직임, 파일 가벼움 | 제작 난이도 높음 | 마스코트 확정 후 |
| **목업에서 잘라내기** | 목업과 100% 동일 | 배경이 같이 딸려옴, 해상도 한계, 요소별 분리 불가 | 비권장 |

## 상업 이용 주의

학교에 납품하는 제품이므로 **라이선스를 반드시 확인**해야 한다.

- AI 생성물: 서비스마다 상업 이용 조건이 다르다. 유료 플랜이 필요한 경우가 많다
- 스톡: 무료 티어는 대개 출처 표기 의무가 있다
- 어느 쪽이든 **최종본은 라이선스 근거를 저장소에 남겨둘 것**

## 진행 순서 제안

1. 유민님이 위 프롬프트로 이미지 생성 (필수 3장: 마스코트 2 포즈 + 선생님)
2. 투명 배경 PNG로 내보내기
3. `public/brand/`에 넣기
4. 내가 `character` / `avatarSrc` prop 연결 + 크기·위치 미세 조정
5. 브라우저에서 확인

현재 SVG는 그때까지 쓰는 **자리 표시용**이다. 교체하면 그대로 사라진다.
